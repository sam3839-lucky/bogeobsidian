# 目标

定时自动处理 `00-Inbox/Downloaded`，把机械性的清洗/去重/提炼自动化，同时严格保留方案 B 的"保底阀门"（人工放行），不让低置信度内容未经把关就进入正式库。

# 核心原则（防踩红线）

1. 不自动移动到 Research / Notes——归位由人工放行（符合导入指南与 Triage 定义）。
2. 低置信度（low）内容留在待核验清单，不自动入库。
3. 原件不覆盖，始终保留在 Downloaded，直到放行或归档。
4. 清洗满足信息无损验证 + 保护区哈希。
5. 临时文件用完即清。

# 三层架构

## 第一层：清洗层（全自动 · 定时触发）

- 定时监控 `00-Inbox/Downloaded`，识别新增/未处理的真实资料。
- 读取原始文件（html / docx / pdf / xlsx / md）。
- 机械规范化：格式整理、表格/图片/代码块保护、去除敏感信息（凭据/Token）。
- 去重：URL / 文件哈希 / 标题。
- 产出：cleaned Markdown 副本 + 每批审计记录。**不移动文件。**

## 第二层：提炼层（AI 自动生成候选）

- 对 cleaned 内容提炼 Markdown 候选笔记（原子笔记 / 方法论 / 数据笔记）。
- 自动标注：主领域、分类、置信度（low/medium/high）、来源、作者、日期、Topic 候选、链接候选。
- 生成"待核验清单"（人工放行的输入）。
- AI 相关文档归 89-Prompts/AI工具使用；房地产/教育走对应子目录。

## 第三层：放行层（人工 · 保底阀门）

- 用户批量浏览待核验清单。
- 放行 → 进入正式库（01-Notes / 04-Research 相应子目录），原件归档到 原始资料/。
- 拒绝 → 99-Archive。
- 来源不可溯 / 版权风险 → 保持 Downloaded 并标记。

# 技术实现

- 触发：Codex 定时自动化（如每日固定时刻唤醒线程）。
- 执行：PowerShell + 内置 Python（复用已验证的中文路径/base64 编码方案）读取并清洗。
- 输出：每批一份处理报告（清单 + 审计），存放于 96-System/Audits。

# 范围界定

- 仅处理 Downloaded 中未处理的真实资料。
- 版权/敏感/来源不可溯内容：保持 Downloaded 并标记，不强行清洗。
- 已处理文件通过标记区分，避免重复处理。

# 评审待办（第一轮）

- 触发频率与空闲期处理策略。
- 去重判定阈值与误判风险。
- cleaned 副本的存放位置与命名。
- 提炼层何时属于"未确认不批量生成"的边界。
- 报告归档的保留策略。
