# 目标

自动处理 `00-Inbox/Downloaded`：机械清洗 + 生成待核验清单 + 人工放行。

核心立场：**自动清洗、自动提炼，人工放行（保底阀门）**。本方案不承诺"全自动无人归位"——进入正式库的动作一律保留人工把关。

# 运行前提（诚实边界，先讲清楚）

1. **当前不上线自动批量**。自动化 Cleaner 的幂等测试与信息无损测试均为 NOT_CHECKED（见 Build-State / Cleaner Spec）。必须先在小规模监督试点通过后，才允许放开批量。
2. **定时自动化未验证前不承诺定时**。默认形态为"手动触发 + 半自动"；只有验证当前环境的 Codex 定时自动化可用后，才升级为定时。
3. **自动批量清洗属重复性写操作**，须用户**显式确认开启**才上线（硬门槛），默认不自动开跑。

# 核心原则（防踩红线）

1. **所有归位一律走第三层人工放行**，包括 AI 文档与房地产/教育内容；任何层不自动移入正式位。
2. 低置信度（low）内容留在待核验清单，不自动入库。
3. 原件不覆盖，始终保留在 Downloaded，直到放行或归档（可回滚）。
4. 清洗满足信息无损验证 + 保护区哈希。
5. **第二层只产出"待核验清单 + 建议草稿"**，不批量写入正式笔记（遵守"未确认不批量生成"红线）。
6. 清洗只做格式规范化，不改写观点；版权 / 来源不可溯内容不强清洗。
7. 临时文件用完即清。

# 文件生命周期与位置

| 阶段 | 文件 | 位置 | 谁触发 |
|---|---|---|---|
| 输入 | 原始文件 | `00-Inbox/Downloaded` | 用户放 / 任务发现 |
| L1 清洗 | `<原名>--cleaned.md` | `00-Inbox/Cleaned` | 运行（原件不动） |
| L2 提炼 | `待核验清单-YYYYMMDD.md` | `00-Inbox/Cleaned` | 运行 |
| L2 审计 | 批次处理报告 | `96-System/Audits` | 运行 |
| L3 放行 | 正式笔记 + 原件归档 | 正式库 / 该领域`原始资料/` / `99-Archive` | 人工 |

# 三层架构

## 第一层：清洗层（机械 · 全自动）

- 扫描 Downloaded，只处理**尚未清洗或未标记 processed** 的真实资料。
- 读取 html / docx / pdf / xlsx / md；每轮**设批处理上限**（小批量，便于监督）。
- 机械规范化：格式整理、表格/图片/代码块保护、敏感信息扫描、去重。
- 产出 `00-Inbox/Cleaned/<原名>--cleaned.md`。**不移动原件。**
- **不可清洗格式**（如 PDF 扫描件 / 无法信息无损的 OCR）：标记 `workflow/error` 或 `quality/needs-verification`，保留 Downloaded，不强清洗。
- 写入状态标记 + 心跳。

## 第二层：提炼层（AI 生成候选 · 只产出清单）

- 读取 cleaned 副本，为每份生成**建议**：主领域、分类、置信度、来源、作者、日期、Topic 候选、链接候选、建议笔记要点。
- **每条建议须引用 cleaned 内容中的来源锚点（原文片段）**，便于人工核验。
- **禁止 AI 虚构作者、日期、链接等来源元数据**；AI 生成内容一律标注"AI 建议"，与原文事实明确分离。
- 全部汇入 `待核验清单-YYYYMMDD.md`。**不写入任何正式笔记文件。**

## 第三层：放行层（人工 · 保底阀门）

- 用户批量浏览待核验清单，**并入 Triage 六维判定**：安全、来源、重复、相关性、可处理性、去向——不能只做"是/否"。
- 放行 → 分配唯一 id、写受控 YAML、移入正式位，原件归档到该领域`原始资料/`。
- 拒绝 → `99-Archive`。
- 来源不可溯 / 版权风险 / 敏感 → 保持 Downloaded 并标记，不强清洗、不放行。
- 放行后执行**链接完整性校验**（附件随迁、内部链接无 broken link）。

# 状态标记与心跳（可见性）

- cleaned 文件 frontmatter：`workflow/status`（waiting-approval / approved / rejected / archived / error）、`workflow/processed: true`、`workflow/cleaned-at`。
- **心跳**：每次运行在 `96-System/Audits` 留"最后运行时间 + 结果 + 失败清单"，供用户一眼判断任务是否成功，避免静默失败。

# 去重规则

- 主键：原始 URL（html 的 canonical/原始 URL）。
- 无 URL：标题规范化 + 文件哈希兜底。
- **registry**：放行时登记 URL/哈希；每次运行前校验 registry 与现有正式库一致，防索引过期漏判。
- 同名不同哈希：判"疑似重复"，记入待核验，不自动丢弃。

# 单文件失败处理

- 失败文件保留原样，标记 `workflow/error` + 错误信息。
- 同批最多重试 1 次；不阻塞整批；批次报告汇总失败清单。

# 敏感信息扫描

- 模式白名单：邮箱、手机号、身份证、银行卡、Token、API Key、私钥、Cookie。
- 命中：标 `quality/sensitive` + 建议 low；正文可留本地库，但放行时提醒"入库到生产目录前需处理"。
- 命中敏感信息的文件一律不放行。

# 待核验清单生命周期

- 条目状态：待核验 → 已放行 / 已拒绝 / 已归档。
- 清单滚动保留最近 30 份（或手动归档）；`96-System/Audits` 批次报告按 `audit/type: inbox-pipeline` 标记，滚动保留最近 30 份或按季度归档。

# 触发方式（分档）
