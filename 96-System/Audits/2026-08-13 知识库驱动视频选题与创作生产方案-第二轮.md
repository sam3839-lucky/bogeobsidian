# 知识库驱动视频选题与创作生产方案（第二轮·评审后完善版·含爆款设计）

> 用途：把已收集的知识库，变成可持续产出的「高流量爆款视频选题 + 文案创作」流程。
> 本文件为第二轮方案，已根据第一轮评审决策 + 爆款专项评审完善。本轮评审通过后，将合并扩写为 Content Production Workflow.md 正式 Guide。

## 1. 背景与目标

当前状态：知识库已有完整的「收集—清洗—归位」进料层，以及内容生产的骨架，但「从库内素材选题 → 常态化产出爆款文案」这一层还没有形成稳定节拍。用户要用这个库做视频文案的选题和创作，目标产出高质量、高流量的爆款作品。

本方案目标（单一、可验收）：**建立一条「知识库 → 竞品拆解 → 选题 → 爆款设计 → 内容 Brief → 口播稿/公众号文稿 → 核验 → 发布 → 数据复盘 → 反哺」的爆款常态化生产流程**，并明确每一环节的产出物、退出条件、分工和所用现有资产。

范围边界（沿用已确认的口径）：
- 内容主领域：房地产。**深圳板块做细化**，全国其他城市作为大类保留，偶尔关注。
- 「为什么买房/财商/教育」是长期可复用的知识素材与题材来源，但**不作为独立主领域**；AI 相关只作方法积累（提示词/用法/经验），**不单独作为选题**。
- 本方案只做「选题与文案」，不含拍摄、剪辑、发布执行或软件界面开发。

## 2. 方案定位（与现有资产的关系）

不另起炉灶，方案补齐缺口并复用现有资产：

- 内容状态机与「单一母稿原则」沿用 Content Production Workflow（idea → brief → draft → review → published → repurpose/archived）。本方案不改其关卡定义，只补充「选题入口」「爆款设计关卡」和「常态化节拍」。**单一母稿原则调整为：一个 Brief 产出两个平台稿（视频号口播稿 + 公众号文稿），各自保留一份母稿，不按平台复制多份。**
- 进料层复用 Research Collection Workflow、Research Triage Guide、00-Inbox 自动清洗归位。本方案把它的输出（04-Research 原始资料 + 原子笔记 + 07-Topics 挂载）当作选题的原料层。
- 与二创试点项目（06-Projects/房地产短视频二创工作流试点）的关系：**并行推进**。试点走「拆解参考视频 → 二创原创稿」，本方案走「库内素材 → 原创选题与创作」。两者互补，互不阻塞。竞品拆解环节复用二创试点的拆解能力，但聚焦于提取可复用的流量密码，不复制文案。
- 模板与提示词复用 90-Templates 以及 89-Prompts/TSC-提示词 下的波哥人设、核心母题创作、口播稿/公众号、黄金 5 秒开图、Hook 库、热门话题漏斗策略等。

## 3. 生产闭环（总览）

完整循环（新增环节以 ★ 标注）：

0. ★ 竞品拆解：每周拆 1 条同赛道爆款，提取流量密码 → 存入知识库 → 反哺选题和爆款设计。
1. 进料/挂载：Inbox 清洗 → 04-Research 原始资料 → 原子笔记（带来源/日期/置信度）→ 挂到 07-Topics 主题枢纽。
2. 选题候选：从主题枢纽 + 原子笔记 + 竞品拆解库提炼「可做选题」，产出到 05-Content/Ideas。
3. 选题清单：汇总候选、排序、定本周期做哪几条。
4. 内容 Brief：按模板落地证据来源、内容结构、核验点。
5. ★ 爆款设计：在 Brief 通过后、创作前，完成爆款设计清单（强制关卡，3 必过 + 4 可选）。
6. 创作 + 发布前核验：从同一 Brief 分别生成两个平台稿，各自走核验清单（含人设一致性检查）。
7. 发布与数据：记录真实日期/链接/表现数据，未采集写「未采集」。
8. ★ 数据复盘：按爆款关键指标逐维度复盘，产出结构化复盘笔记，反哺选题和爆款设计。

★ 热点快速响应通道：独立子流程。当触发条件满足时，跳过环节 2 和 3，直接进入 Brief → 爆款设计 → 创作 → 核验。

## 4. 各环节详细设计

每环节给出：输入 → 动作 → 产出物（位置）→ 退出条件 → 负责 → 用到的现有资产。

### 0. 竞品拆解（★ 新增，常态化进料）

> 落地阶段：第一批跑通 3 条闭环后启动。每周固定拆 1 条。

- 输入：同赛道（深圳房产）近 7 天播放量最高的视频（不限账号）。
- 动作：结构化拆解，提取可复用的流量密码，不复制文案。
- 拆解维度：
  - Hook 类型（反常识断言 / 数据冲击 / 痛点共鸣 / 悬念提问 / 其他）
  - 情绪曲线（开头→中段→结尾的情绪变化）
  - 争议点设计（有没有故意制造认知冲突？什么冲突？）
  - 互动设计（评论区引导方式、CTA 策略）
  - 可复用模式（这条视频的「流量公式」是什么？）
- 产出：05-Content/Ideas/竞品拆解-<日期>-<视频关键词>.md
- 退出条件：五个拆解维度完整填写，且提取出至少 1 个可复用模式。
- 负责：我拆解 → 用户确认可复用模式。
- 资产：二创试点拆解方法论、黄金 5 秒开图、Hook 库。

### ① 进料与挂载（原料层）
- 输入：新下载/新收集的素材。
- 动作：沿用现有清洗归位，提炼原子笔记并挂到对应 07-Topics 枢纽；官方数据优先，观点类标注「观点来源」与置信度。
- 产出：04-Research/原始资料 + 原子笔记 + 07-Topics 挂载。
- 退出条件：每条素材可追溯来源 URL、日期、观点 vs 数据、置信度。
- 负责：我（清洗/提炼初稿）→ 用户（确认归类）。
- 资产：Research 相关 Guide、待核验清单、Atomic Note Template。

### ② 选题候选生成
- 输入：07-Topics 枢纽 + 原子笔记 + 待核验清单里已放行的素材 + 竞品拆解库。
- 动作：从每条素材提炼 1 个或多个「可做选题」，标注：主题枢纽、切入角度、素材锚点、观点 vs 数据、置信度、时效性、建议形式（口播/图文/双稿）、可复用性。**起步阶段只筛选深圳相关选题。** 选题时参考竞品拆解库中的流量密码，标注「可借鉴的爆款模式」。
- 产出：05-Content/Ideas/选题候选-<日期>.md（一张候选表，按枢纽分组）。不建空目录、不预设空结构。
- 退出条件：每个候选必须锚定到至少一条原子笔记或官方数据；无依据的候选不保留；观点类候选显式标「待核验」。
- 负责：我生成候选初表 → 用户增删/圈选。
- 资产：89-Prompts 下的核心母题/选题/黄金 5 秒开图、Hook 库、竞品拆解库。

### ③ 选题清单与排期（决策层）
- 输入：选题候选表。
- 动作：按优先级（时效性、深圳优先、可复用性、证据成熟度、爆款潜力）排序，形成 backlog；定「本周期做 3–5 条」。
- 产出：05-Content/Ideas/选题清单.md（维护中的 backlog 索引）。
- 退出条件：明确每条候选的优先级与是否本周期做；被否的候选记原因（或归档），不静默丢弃。
- 负责：用户拍板选题；我提供排序建议。

### ④ 内容 Brief（立案）
- 输入：被圈选的选题候选。
- 动作：按 Content Brief Template 填写：目标平台（视频号+公众号）、目标受众、核心观点、证据来源、内容结构、核验点。**一个 Brief 同时覆盖两个平台，在内容结构中标注口播与公众号的差异要点。**
- 产出：05-Content/Briefs/<题> - Brief.md。
- 退出条件：双平台已标注、受众/核心观点/证据来源/内容结构/核验点齐全；证据可追溯。
- 负责：我起草 → 用户审核。

### ⑤ 爆款设计（★ 新增，强制关卡）

> 在 Brief 通过后、进入创作前，必须通过此关卡。不通过不进入创作。

- 输入：已通过审核的 Brief + 竞品拆解库 + Hook 库 + 黄金 5 秒开图。
- 动作：逐项完成爆款设计清单。

**必过项（3 项，缺一不可）：**

| 检查项 | 要求 | 产出 |
|--------|------|------|
| Hook 设计 | 用黄金 5 秒开图生成至少 3 个开头方案，标注预期情绪效果（好奇/震惊/共鸣/愤怒/焦虑） | 3 个 Hook 方案 |
| 标题备选 | 至少 3 个标题方案，标注各自吸引的用户画像 | 3 个标题 + 画像 |
| 情绪曲线 | 画出内容各段的预期情绪变化（痛点→共鸣→认知颠覆→解决方案→行动号召） | 情绪曲线图/描述 |

**可选项（4 项，尽量完成，缺了标注原因）：**

| 检查项 | 要求 |
|--------|------|
| 标签策略 | 按热门话题漏斗公式组合（1 泛流量 + 2 垂直 + 2-3 精准痛点），风控注意用安全热词 |
| 互动钩子 | 评论区引导话术、争议点设计、转发诱因 |
| 封面方向 | 封面核心视觉元素和文字方向（不要求成品图，只要求方向描述） |
| 信息密度节奏 | 每 15 秒段落的信息点/情绪点密度检查，避免中段信息塌方 |

- 产出：05-Content/Ideas/<题> - 爆款设计.md（附在选题候选或 Brief 同目录）
- 退出条件：3 必过项全部完成，4 可选项完成或标注缺失原因。
- 负责：我生成爆款设计清单 → 用户审核通过 → 放行进入创作。

### ⑥ 创作 + 发布前核验（成稿）
- 输入：通过审核的 Brief + 通过审核的爆款设计清单。
- 动作：从同一 Brief 分别生成两个平台稿：
  - **视频号口播稿**：用 89-Prompts（波哥人设 + 口播稿提示词），口语化、时长可控。严格遵循爆款设计清单中的 Hook 方案、情绪曲线和标题方向。
  - **公众号文稿**：用 89-Prompts（公众号文案提示词），书面表达、带段落结构。标题和开头遵循爆款设计清单。
  - 两稿均走发布前核验清单。
- 产出：
  - 05-Content/Scripts/<题> - 视频号口播稿.md
  - 05-Content/Scripts/<题> - 公众号文稿.md
- 退出条件：两稿母稿完成、事实边界标注、核验清单全过、用户人工验收。

**发布前核验清单（全覆盖）：**

- [ ] 事实核验：数据口径（环比/同比/城市层级）、来源可追溯、日期明确
- [ ] 版权核验：不复制参考视频完整文案、独特表达、个人经历或创作者人格
- [ ] 广告合规：不使用「最佳时机 / 全面回暖 / 稳赚」等绝对化表达；引用数据带口径
- [ ] 公众号额外风控：不洗稿、不直接复制源文章段落；转载/引用标注来源；不使用违规诱导点击标题
- [ ] ★ 人设一致性检查（强制）：每一段是否通过了「波哥人设测试」？
  - 能不能让卖菜阿姨听懂？
  - 有没有用生活中的比喻（身体/汽车/恋爱/天气）？
  - 有没有毒舌味？
  - 有没有「降维翻译」——把专业术语翻成大白话？
- [ ] 爆款设计还原度：实际成稿是否还原了爆款设计清单中的 Hook 方案、情绪曲线和标题方向？
- [ ] 口播实测时长不超过目标时长；如超时，优先删减修辞，不删除事实边界
- [ ] 发布前完成一次逐句人工核验

- 负责：我生成初稿 + 清单 → 用户人工验收（程序/AI 不得自行宣布验收通过）。

### ⑦ 发布与表现数据
- 输入：通过验收的母稿。
- 动作：用户发布后，记录真实发布日期/链接/表现数据；未采集写「未采集」，不虚填。
- 产出：Brief/Script 内更新状态与数据字段。
- 退出条件：状态更新为 published，数据项有来源与采集日期。
- 负责：用户提供发布事实与数据；我记录。

### ⑧ 数据复盘（★ 升级，爆款关键指标）

> 落地阶段：第一批跑通 3 条闭环后，正式启用完整指标维度。第一批 3 条期间，有多少数据记多少，用于建立基线。

- 输入：发布后的表现数据 + 制作过程记录 + 爆款设计清单。
- 动作：按以下维度逐项复盘，区分观察/推断/下一轮实验。

**爆款复盘指标维度（预设，数据不齐时写「未采集」）：**

| 指标 | 用途 | 爆款参考线 |
|------|------|-----------|
| 5 秒完播率 | Hook 是否有效 | > 70% |
| 整体完播率 | 内容是否有信息密度 | > 30% |
| 互动率（评论+点赞+收藏）/ 播放 | 是否有争议/共鸣/实用价值 | > 5% |
| 转发率 | 是否有社交货币 | > 2% |
| 评论区高频词 | 观众真正关心什么 | 提取 Top 5 关键词 |
| 与同类选题横向对比 | 是选题问题还是执行问题 | 与竞品拆解库对照 |

- 产出：每批内容一份复盘笔记（可挂到 05-Content 或相关 Topic），包含：
  - 实际表现 vs 爆款设计预期
  - 观察（数据事实）
  - 推断（可能原因）
  - 下一轮实验（改进假设）
- 退出条件：复盘区分三类结论，且有明确下一轮改进项；关键指标至少填写「已采集」或「未采集」。
- 负责：我起草复盘 → 用户确认。

**复盘反哺机制：**
- 「哪类 Hook 效果好/差」→ 写回竞品拆解库和 Hook 库
- 「哪类选题数据好/差」→ 写回选题候选优先级排序逻辑
- 「哪个情绪曲线模式表现好」→ 写回爆款设计清单模板

## 5. 热点快速响应通道（★ 新增，独立子流程）

> 落地阶段：第一批跑通 3 条闭环后启用。

### 触发条件（写死，防止滥用）

以下任一事件发生时，可启动热点快速响应：
- 深圳出台房地产相关政策（限购/限贷/税费/公积金/人才房等）
- 国家统计局发布月度 70 城房价数据
- 深圳土拍出现重大结果（流拍/高溢价/新地王）
- 深圳新房开盘去化率显著异常（日光或去化率 < 10%）

### 流程（压缩版）

常规流程：竞品拆解 → 进料 → 选题候选 → 选题清单 → Brief → 爆款设计 → 创作 → 核验 → 发布 → 复盘

热点快速通道：**触发事件 → Brief → 爆款设计 → 创作 → 核验 → 发布 → 复盘**

- 跳过「选题候选」和「选题清单」——热点本身就是选题，不需要候选。
- 其他关卡不变（Brief、爆款设计、核验、复盘全部保留，质量不妥协）。
- 时效目标：事件发生后 24 小时内完成 Brief + 爆款设计，48 小时内完成创作 + 核验。

### 与常规周更的关系

- 热点触发时，热点优先于常规周更。
- 如果热点导致本周常规产出减少，在复盘时标注原因，不计入周更达标率考核。

## 6. 节拍与节奏

- **起步阶段**：先跑通 3 条完整闭环（含 1 条已发布样板作为基准对照），验证流程可行性，再进入常态。起步阶段只做第一批升级（爆款设计关卡 + 人设一致性检查），竞品拆解和热点响应暂不启动。
- **常态**：每周 3–5 条常规内容 + 每周 1 条竞品拆解。每条需经爆款设计关卡、事实核验与人工验收。宁少但每条过核验，不批量堆未验收内容。
- 每条从 Brief 到验收预计 2–4 轮交互（取决于核验与改稿次数）。

> 风险提示：每周 3–5 条 + 1 条竞品拆解，意味着每条常规内容平均只有 1–2 个工作日。如果事实核验、爆款设计、改稿、人工验收的轮次超出预期，实际产出可能低于目标。建议起步阶段观察实际耗时，再校准常态目标。

## 7. 质量与风控（底线，不可妥协）

- 官方数据优先；观点类内容显式标注来源与低置信度，进入文案前重新核验数据是否过期。
- 不虚填日期、链接、表现数据；未采集写「未采集」。
- 版权：参考/二创只学结构与机制，不复制参考视频完整文案、独特表达、个人经历或创作者人格。
- 广告合规：不使用「最佳时机 / 全面回暖 / 稳赚」等绝对化表达；引用数据带口径（环比/同比/城市层级）。
- 公众号稿额外风控：不洗稿、不直接复制源文章段落；转载/引用标注来源；不使用违规诱导点击标题。
- 爆款与合规的平衡：爆款设计可以制造认知冲突和情绪张力，但不能以牺牲事实准确性为代价。争议可以来自于「挑战常识」，但不能来自于「歪曲数据」。
- 发布前逐句人工核验；状态机与 Review 纪律沿用 Content Production Workflow。

## 8. 分工与我的角色

- 我：生成选题候选、起草 Brief、生成爆款设计清单、生成初稿（口播 + 公众号）、整理核验清单与复盘、每周拆解 1 条竞品；但不代为验收、不宣布发布、不决定平台。
- 用户：拍板选题、审核爆款设计清单、人工验收每条文案（口播 + 公众号）、提供发布事实与表现数据、决定平台与节奏。

## 9. 里程碑（两阶段落地）

### 第一批（立即，方案通过后即执行）

- M0：本方案评审通过，合并扩写为 Content Production Workflow.md 正式 Guide。
- M1：基于现有库内素材，生成第一批深圳选题候选清单（05-Content/Ideas/选题候选-<日期>.md）。
- M2：用户圈选 3 题，完成 3 条内容 Brief + 3 份爆款设计清单。
- M3：完成 3 条视频号口播稿 + 3 条公众号文稿（含人设一致性检查）+ 发布前核验 + 用户验收。
- M4：3 条全部发布后，用已有数据完成第一批复盘（数据不齐的维度标注「未采集」，建立基线）。

### 第二批（跑通 3 条闭环后启动）

- M5：启动每周竞品拆解（每周 1 条，产出到 05-Content/Ideas/竞品拆解-<日期>.md）。
- M6：启动热点快速响应通道（首次触发事件后执行，验证 48 小时时效）。
- M7：启用完整复盘指标维度，第一批复盘基线作为对照。
- M8：固化周更节拍（3–5 条常规 + 1 条竞品拆解），完成第二轮复盘。

## 10. 本方案未涉及（明确排除）

- 拍摄、剪辑、发布执行、账号运营与投流。
- 软件/界面/自动化开发（另立项目）。
- AI 技术本身的选题（仅作方法积累，不单独选题）。
- 全国大类城市选题（保留但暂不主动进选题；深圳起步）。
- 封面成品设计（方案只到封面方向描述，成品设计由用户或设计师完成）。
