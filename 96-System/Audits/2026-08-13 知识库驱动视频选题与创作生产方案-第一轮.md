# 知识库驱动视频选题与创作生产方案（第一轮·待评审）

> 用途：把已收集的知识库，变成可持续产出的「视频选题 + 文案创作」流程。
> 本文件为第一轮方案，评审通过并完善后才固化为正式规则；评审前不据此执行或改动目录。

## 0. 背景与目标

当前状态：知识库已有完整的「收集—清洗—归位」进料层，以及内容生产的骨架，但「从库内素材选题 → 常态化产出文案」这一层还没有形成稳定节拍。用户要用这个库做视频文案的选题和创作。

本方案目标（单一、可验收）：**建立一条「知识库 → 选题 → 内容 Brief → 口播稿/公众号文稿 → 核验 → 发布 → 复盘」的常态化生产流程**，并明确每一环节的产出物、退出条件、分工和所用现有资产。

范围边界（沿用已确认的口径）：
- 内容主领域：房地产。**深圳板块做细化**；全国其他城市作为大类规划，偶尔关注。
- 「为什么买房/财商/教育」是长期可复用的知识素材与题材来源，但**不作为独立主领域**；AI 相关只作方法积累（提示词/用法/经验），**不单独作为选题**。
- 本方案只做「选题与文案」，不含拍摄、剪辑、发布执行或软件界面开发。

## 1. 方案定位（与现有资产的关系）

不另起炉灶，方案补齐缺口并复用现有资产：

- 内容状态机与「单一母稿原则」沿用 Content Production Workflow（idea → brief → draft → review → published → repurpose/archived）。本方案不改其关卡定义，只补充「选题入口」和「常态化节拍」。
- 进料层复用 Research Collection Workflow、Research Triage Guide、00-Inbox 自动清洗归位（Inbox自动清洗归位方案已多轮评审）。本方案把它的输出（04-Research 原始资料 + 原子笔记 + 07-Topics 挂载）当作选题的原料层。
- 与二创试点项目（06-Projects/房地产短视频二创工作流试点）的关系：试点走「拆解参考视频 → 二创原创稿」，本方案走「库内素材 → 原创选题与创作」。两者互补；建议试点先收尾或并行受控，不在试点中途叠一套新流程（见 §8 待评审问题）。
- 模板与提示词复用 90-Templates（Content Brief / Atomic Note / Topic Hub）以及 89-Prompts/TSC-提示词 下的波哥人设、核心母题创作、口播稿/公众号、黄金5秒开图、Hook 库等。

## 2. 生产闭环（总览）

以下为完整循环，各环节对应 §3 的详细设计：

1. 进料/挂载：Inbox 清洗 → 04-Research 原始资料 → 原子笔记（带来源/日期/置信度）→ 挂到 07-Topics 主题枢纽。
2. 选题候选：从主题枢纽与原子笔记提炼「可做选题」，产出到 05-Content/Ideas。
3. 选题清单：汇总候选、排序、定本周期做哪几条。
4. 内容 Brief：按模板落地证据来源、内容结构、核验点。
5. 创作 + 发布前核验：生成单一主稿（口播稿/公众号稿），走核验清单。
6. 发布与数据：记录真实日期/链接/表现数据，未采集写「未采集」。
7. 复盘：区分观察/推断/下一轮实验，反哺选题。

## 3. 各环节详细设计

每环节给出：输入 → 动作 → 产出物（位置）→ 退出条件 → 负责 → 用到的现有资产。

### ① 进料与挂载（原料层）
- 输入：新下载/新收集的素材。
- 动作：沿用现有清洗归位，提炼原子笔记并挂到对应 07-Topics 枢纽；官方数据优先，观点类标注「观点来源」与置信度。
- 产出：04-Research/原始资料 + 原子笔记 + 07-Topics 挂载。
- 退出条件：每条素材可追溯来源 URL、日期、观点 vs 数据、置信度。
- 负责：我（清洗/提炼初稿）→ 用户（确认归类）。
- 资产：Research 相关 Guide、待核验清单、Atomic Note Template。

### ② 选题候选生成（新增的核心环节）
- 输入：07-Topics 枢纽 + 原子笔记 + 待核验清单里已放行的素材。
- 动作：从每条素材提炼 1 个或多个「可做选题」，标注：主题枢纽、切入角度、素材锚点、观点 vs 数据、置信度、时效性、建议形式（口播/图文）、可复用性。
- 产出：05-Content/Ideas/选题候选-<日期>.md（一张候选表，按枢纽分组）。不建空目录、不预设空结构。
- 退出条件：每个候选必须锚定到至少一条原子笔记或官方数据；无依据的候选不保留；观点类候选显式标「待核验」。
- 负责：我生成候选初表 → 用户增删/圈选。
- 资产：89-Prompts 下的核心母题/选题/黄金5秒开图、Hook 库。

### ③ 选题清单与排期（决策层）
- 输入：②的候选表。
- 动作：按优先级（时效性、深圳优先、可复用性、证据成熟度）排序，形成 backlog；定「本周期做 1–2 条」。
- 产出：05-Content/Ideas/选题清单.md（维护中的 backlog 索引）。放 Ideas 下，不新建文件夹。
- 退出条件：明确每条候选的优先级与是否本周期做；被否的候选记原因（或归档），不静默丢弃。
- 负责：用户拍板选题；我提供排序建议。

### ④ 内容 Brief（立案）
- 输入：被圈选的选题候选。
- 动作：按 Content Brief Template 与现有样板格式（如 一线城市房价上涨… - Brief.md）填写：目标平台、目标受众、核心观点、证据来源、内容结构、核验点。
- 产出：05-Content/Briefs/<题> - Brief.md。
- 退出条件：目标平台（可待补充）/受众/核心观点/证据来源/内容结构/核验点齐全；证据可追溯。
- 负责：我起草 → 用户审核。

### ⑤ 创作 + 发布前核验（成稿）
- 输入：通过审核的 Brief。
- 动作：用 89-Prompts（波哥人设 + 口播稿/公众号提示词）生成初稿；走发布前核验清单（事实/版权/广告合规/隐私/平台适配/时长）。
- 产出：05-Content/Scripts/<题> - 视频号口播稿.md（单一主稿，不复制成多平台失控母稿；公众号文稿按需以关联 Brief 或发布记录表达）。
- 退出条件：单一主稿、事实边界标注、口语自然、时长可控、核验清单全过、用户人工验收。
- 负责：我生成初稿 + 清单 → 用户人工验收（程序/AI 不得自行宣布验收通过）。

### ⑥ 发布与表现数据
- 输入：通过验收的主稿。
- 动作：用户发布后，记录真实发布日期/链接/表现数据；未采集写「未采集」，不虚填。
- 产出：Brief/Script 内更新状态与数据字段。
- 退出条件：状态更新为 published，数据项有来源与采集日期。
- 负责：用户提供发布事实与数据；我记录。

### ⑦ 复盘与反哺
- 输入：发布后的表现数据 + 制作过程记录。
- 动作：写复盘，区分观察/推断/下一轮实验；把「哪类选题数据好/差」写回 ②，影响后续选题排序。
- 产出：每批内容一份复盘（可挂到 05-Content 或相关 Topic）。
- 退出条件：复盘区分三类结论，且有明确下一轮改进项。
- 负责：我起草复盘 → 用户确认。

## 4. 节拍建议

- 起步：先跑通 3 条完整闭环（含 1 条已发布样板作为基准对照），验证流程可行性，再固化周更。
- 常态：建议每周 1–2 条（视事实核验与人工验收时间而定）。宁少但每条过核验，不批量堆未验收内容。
- 每条 D→G 预计 2–4 轮交互（取决于核验与改稿次数）。

## 5. 质量与风控（底线，不可妥协）

- 官方数据优先；观点类内容显式标注来源与低置信度，进入文案前重新核验数据是否过期。
- 不虚填日期、链接、表现数据；未采集写「未采集」。
- 版权：参考/二创只学结构与机制，不复制参考视频完整文案、独特表达、个人经历或创作者人格。
- 广告合规：不使用「最佳时机 / 全面回暖 / 稳赚」等绝对化表达；引用数据带口径（环比/同比/城市层级）。
- 发布前逐句人工核验；状态机与 Review 纪律沿用现有 Content Production Workflow。

## 6. 分工与我的角色

- 我：生成选题候选、起草 Brief、生成初稿、整理核验清单与复盘；但不代为验收、不宣布发布、不决定平台。
- 用户：拍板选题、人工验收每条文案、提供发布事实与表现数据、决定平台与节奏。

## 7. 里程碑（评审通过后落地）

- M0：本方案评审通过，完善为可执行规则。
- M1：基于现有库内素材，生成第一批选题候选清单（05-Content/Ideas/选题候选-<日期>.md）。
- M2：用户圈选 1–2 题，完成对应 2 条内容 Brief。
- M3：完成 2 条口播稿 + 发布前核验 + 用户验收。
- M4：跑通 3 条闭环后，固化周更节拍并完成第一批复盘。

## 8. 待评审问题（需要你拍板）

1. 节拍：每周几条？起步先跑 3 条闭环是否认可？
2. 范围：起步只做深圳板块，还是全国大类也同步进选题？
3. 平台：只做视频号口播稿，还是每条同时产出公众号文稿？
4. 选题清单位置：放 05-Content/Ideas/ 内建索引是否合适，还是你另有偏好？
5. 与二创试点项目的关系：并行推进，还是先收尾试点再上这套流程？
6. 本方案评审通过后，是否与现有 Content Production Workflow.md 合并/扩写为正式 Guide，还是单独保留为一份独立规则？

## 9. 本方案未涉及（明确排除）

- 拍摄、剪辑、发布执行、账号运营与投流。
- 软件/界面/自动化开发（另立项目）。
- AI 技术本身的选题（仅作方法积累，不单独选题）。
