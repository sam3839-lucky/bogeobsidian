# Architecture Decisions

## ADR-001：以 E:\波哥Obsidian 作为唯一 Vault 根目录

- 状态：已接受
- 日期：2026-08-09 12:32:50 +08:00
- 背景：阶段 0 发现 `.obsidian` 曾位于下一层目录；用户已将 Vault 内容移至 `E:\波哥Obsidian`，复核确认根目录直接包含 `.obsidian`。
- 决策：后续所有相对路径均以 `E:\波哥Obsidian` 为根，不再使用 `波哥财道` 子目录作为 Vault。
- 影响：避免在 Vault 外误建知识库结构；任何写入前仍须验证根目录存在 `.obsidian`。

## ADR-002：Git 初始化前使用 Vault 外时间戳压缩快照

- 状态：已接受
- 日期：2026-08-09 12:32:50 +08:00
- 背景：当前 Vault 不是 Git 仓库，无法使用 commit 作为回滚点。
- 决策：阶段 1 使用 `E:\波哥Obsidian-Backups\波哥Obsidian-20260809-123250.zip` 作为回滚点；备份位于 Vault 外，不覆盖旧备份。
- 影响：恢复时须先保护当前状态，再将快照解压回 Vault；Git 初始化留待后续明确阶段。

## ADR-003：系统记录与业务知识结构分离

- 状态：已接受
- 日期：2026-08-09 12:32:50 +08:00
- 背景：需要跨阶段记录执行状态，但本阶段禁止改变业务知识结构。
- 决策：仅在 `96-System` 下建立日志与架构决策文件，不创建 AI、房地产、小孩教育或内容平台目录。
- 影响：业务目录设计必须由后续阶段单独决策与执行。
## ADR-004：Git 跟踪边界与私有远端

- 状态：已接受
- 日期：2026-08-09 12:48:51 +08:00
- 背景：Vault 需要版本回滚能力，用户提供私有仓库 `https://github.com/sam3839-lucky/bogeobsidian`；设备工作区状态及凭据不应进入版本历史。
- 决策：使用 `main` 分支和 `origin` 私有远端；跟踪可复用的 Obsidian 配置与知识文件，忽略 `workspace.json`、缓存、回收站、临时文件及常见凭据文件。
- 影响：插件 `data.json` 默认不纳管，避免意外提交插件令牌，但部分插件个性化设置不会随 Git 同步。禁止 Force Push；远端已有历史时必须先审查再决定整合方式。
- 实施结果：首次 Push 已通过 Clash Verge 一次性代理完成；代理未写入 Git 全局配置；验证提交为 `6cea82b8d142031edd8e91709e252e9119b00e76`。
## ADR-005：采用按需落地的最小目录架构

- 状态：已接受
- 日期：2026-08-09 13:09:48 +08:00
- 背景：目标结构包含多个生命周期与研究目录，但当前业务内容只有根目录 `欢迎.md`。创建空目录无法进入 Git，使用大量 `.gitkeep` 会制造虚假完成感和维护噪音。
- 决策：完整定义目标目录职责，但仅在出现首个真实内容或本阶段指定文件时创建目录。本阶段只新增有实际治理文档承载的 `96-System/Guides`。
- 影响：目标结构将逐步出现，而不是一次性铺满；目录是否存在不能单独代表功能是否完成。

## ADR-006：目录表达职责与生命周期，Topic 表达关联

- 状态：已接受
- 日期：2026-08-09 13:09:48 +08:00
- 背景：AI、房地产、小孩教育可能同时参与研究、项目和内容生产；若用多套深层目录表达所有交叉关系，会导致重复文件和版本分叉。
- 决策：每份知识只有一个主存放位置；目录表示主要职责或生命周期，Topic、链接及后续元数据表示跨领域关系。目录原则上不超过三层。
- 影响：跨领域内容不得复制到多个研究目录；`07-Topics` 只在已有真实笔记需要导航时创建。
## ADR-007：采用统一基础 Properties 与类型状态兼容表

- 状态：已接受
- 日期：2026-08-09 13:24:43 +08:00
- 背景：不同笔记需要统一检索字段，但强迫每类笔记填写全部字段会制造虚假数据。
- 决策：所有新笔记共享英文基础字段；`id`、`type`、`title`、`status`、`created` 通用必填，其余按类型条件填写。`domain` 最多一个，`topics` 可多选，`tags` 只承担注册的操作性信号。
- 影响：现有笔记不批量注入 YAML；新增字段、类型、状态或标签必须先修改治理规范。

## ADR-008：核心模板使用无插件静态 YAML

- 状态：已接受
- 日期：2026-08-09 13:24:43 +08:00
- 背景：当前未安装模板自动化插件，动态占位符无法可靠解析，也可能生成虚构日期或标识。
- 决策：11 个核心模板使用 Obsidian 原生静态 YAML；必填实例值保持空字符串，并在复制后手工填写。验证采用真实审计记录，不创建 Topic Hub 或伪知识。
- 影响：创建笔记时需要手工生成 `id` 和日期；自动化只能在未来插件阶段经确认后增加，且必须保留无插件版本。
## ADR-009：Cleaner 采用原件不可变与双工件输出

- 状态：已接受
- 日期：2026-08-09 13:40:41 +08:00
- 背景：格式清理可能误删观点、来源、代码、表格或导航内容，直接覆盖原件会失去审计和回滚能力。
- 决策：Downloaded 原件不可变；Cleaner 只生成新的 cleaned 副本和独立审查清单。分类、Topic 与链接仅作为 AI 或规则建议，不写入原文事实区。
- 影响：存储会暂时保留原件与清理副本，但正式知识仍只有一个主位置；原件的后续处置必须单独批准。

## ADR-010：Triage 与 Reviewed 是人工关卡，不扩展受控 status

- 状态：已接受
- 日期：2026-08-09 13:40:41 +08:00
- 背景：阶段 4 流程包含 Triage 和 Reviewed，但阶段 3 已定义受控 `status`，直接加入新值会破坏元数据治理。
- 决策：Triage 和 Reviewed 作为流程关卡记录在审查清单中，不创建同名目录，也不新增 `status` 值。自动化只生成建议，正式流转由人工确认。
- 影响：当前可进行单文件人工监督试运行；自动化 Cleaner 未实现前禁止批量运行。
