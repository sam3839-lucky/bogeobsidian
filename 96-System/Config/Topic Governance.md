# Topic Governance

## 目的

Topic Hub 是基于真实内容形成的导航和研究界面，不是为了让目录看起来完整。词频只能发现候选，不能单独证明应建立 Hub。

## 准入条件

默认同时满足以下条件才可创建 Hub：

1. 至少 3 份真实且语义相关的研究、来源、原子笔记、项目或内容文件；或至少 2 份真实文件并存在明确的活跃项目/创作需求。
2. Topic 有跨时间的复用价值，不是一次性关键词。
3. 可以写出清晰的范围与排除边界。
4. 没有更合适的同义 Hub。
5. 有明确维护责任和复审触发条件。

声明的主领域、目录名称、单篇文章高频词和模板内容都不能单独成为建 Hub 的证据。

## 候选记录格式

每个候选必须记录：

- 主领域
- Topic 名称
- `aliases`
- 相关真实文件数
- 建立 Hub 的理由
- 不建立 Hub 的理由
- 长期价值
- 当前研究重点匹配度
- 项目或创作需求
- 维护成本
- 同义 Topic 风险
- 置信度：`low`、`medium` 或 `high`

## 评分框架

每项使用 0–2 分：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 长期价值 | 一次性 | 可能复用 | 长期核心问题 |
| 语义关系 | 仅词面相似 | 部分相关 | 有明确问题链或证据链 |
| 当前重点 | 无关 | 次要 | 当前核心研究方向 |
| 项目/创作需求 | 无 | 潜在 | 已有明确需求 |
| 可维护性 | 边界模糊或重复 | 可维护但成本高 | 边界清楚且可持续 |

默认总分至少 7/10，且满足最少真实文件数，才能提交创建确认。分数不能替代人工判断。

## 同义词与规范名称

- 一个概念只保留一个规范 Topic 名称。
- 常见变体、英文名、缩写放入 `aliases`。
- 大小写、单复数或翻译差异不能自动生成多个 Hub。
- 发现同义 Hub 时先提交映射、链接影响和合并方案；未经确认不得移动、重命名或合并。

## Hub 文件规则

Hub 使用 `Topic Hub Template.md`，YAML `type` 为 `topic-hub`，`status` 仅使用阶段 3 已允许的 `active`、`deprecated`、`archived`。

正文必须包含：

- 定义
- 范围与边界
- 核心问题
- 关键概念
- 重要来源
- 原子笔记
- 相关项目
- 相关 Prompt
- 内容输出
- 未解决问题
- 最近更新时间

没有内容的章节保留问题或维护说明，不能填充虚构链接和伪知识。

## Topic Index 激活条件

`07-Topics/Topic Index.md` 只在第一个经过确认的真实 Hub 创建时一并建立。没有 Hub 时不创建空索引。

Topic Index 只列出规范 Topic 名称、主领域、状态和 Hub 链接，不复制 Hub 正文。

## 链接规则

- 自动或批量添加链接前必须验证目标文件唯一存在。
- 链接必须表达定义、证据、反例、延伸、项目输入、Prompt 支持或内容来源之一。
- 仅因出现相同词语不得添加链接。
- 不创建空文件满足链接。
- 试点每次只处理少量代表性文件，并保留 Git Diff。

## 维护与退役

- 最近更新时间必须使用 `YYYY-MM-DD`。
- 当边界变化、出现同义 Hub、相关文件长期不足或研究重点结束时复审。
- 不再维护但仍有价值时改为 `deprecated` 或 `archived`，不得静默删除。
- 合并、移动、重命名或批量改链接必须展示影响并获得确认。
