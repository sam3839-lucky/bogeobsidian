# 房地产内容分类规则

本文件定义 `04-Research/房地产` 的内容细分与 Inbox 后期处理规则。
核心原则：先定规则、不建空目录、内容到了才建目录；分类统一交给 AI 判定，AI 判定清晰则自动归类，判定模糊则标记待核验。

## 一、三层内容模型（ADR-017）

| 层 | 含义 | 落地目录 | 存放 | 不存放 |
|---|---|---|---|---|
| ① 内容主题域（仓库） | 房地产（主、深圳细化）＋小孩教育＋财商 | `04-Research/` | 原始来源、观点、市场数据、板块分析 | 生产草稿、AI 技术 |
| ② 生产层（加工厂） | 知识→选题→文案 | `05-Content/` + `01-Notes/` | 原子笔记、选题清单、Brief、脚本、发布记录 | 原始下载、研究原件 |
| ③ 能力层（磨刀石） | AI 使用经验，纯内部 | `89-Prompts/` `97-AI-Memory/` `98-AI-Context/` `96-System/` | 提示词经验、知识库搭建方法、AI 工作流 | 房地产业务正文、对外选题 |

AI 不是内容主题，是生产工具与方法层。`04-Research/AI` 不再作为内容主题位使用。

### 小孩教育的定位

- 小孩教育 = 纯知识仓库：只用于存放和需要时查询，**不进入生产层**（不生成选题清单、不做视频号/公众号文案）。
- 它与房地产的关键区别：房地产是「主题域＋生产」双职责；小孩教育只有「知识存放」单职责。
- 因此小孩教育内容不流向 `05-Content/`，不生成 content-brief，不参与选题。

## 二、房地产细分（深圳细化，其他城市泛化）

`04-Research/房地产/` 下按内容用途细分，目录仅在出现首个真实内容时创建：

| 子目录 | 存放 | 不存放 |
|---|---|---|
| `政策` | 房地产政策（限购、贷款、税费、规划） | 具体成交数据 |
| `板块分析` | 深圳各板块/片区分析与对比 | 全市场行情 |
| `选房策略` | 深圳买房选房方法论与策略 | 政策原文 |
| `房产咨询` | 房产咨询方法论与诊断工具（如 G.P.S. 房产诊断系统） | 政策原文、生产草稿 |
| `为什么买房` | 常驻常识题材（为什么买房、买房价值） | 一次性数据 |
| `市场行情` | 新房/二手房价格指数、市场数据 | 具体土拍个案 |
| `热点事件/土拍` | 土拍情况 | 其他成交 |
| `热点事件/成交` | 成交情况（重点深圳，偶带国内其他城市） | 政策分析 |
| `其他城市` | 深圳以外的城市（大类泛化，不细分） | 深圳内容 |
| `原始资料` | 已加工归档的原始下载（位置即状态） | 未处理原件 |

## 三、细分边界优先级

内容同时命中多个子类时，按主维度优先：
1. 内容本质是政策 → `政策`
2. 内容本质是成交/土拍个案 → `热点事件/成交` 或 `热点事件/土拍`
3. 内容本质是市场指数/数据 → `市场行情`
4. 内容本质是板块/片区 → `板块分析`
5. 内容本质是选房方法 → `选房策略`
5.1 内容本质是咨询/估值方法（如 G.P.S.） → `房产咨询`
6. 内容本质是买房价值/常识 → `为什么买房`

优先级示例：深圳土拍政策调整 → `政策`；深圳某地块成交 → `热点事件/土拍`。

## 四、Inbox 后期处理管线（AI 统一分类）

`00-Inbox/Downloaded`（原始）→ AI 判定 → 细分 → 归档/提炼 → 生产

| 步骤 | 规则 | 去向 |
|---|---|---|
| 1. 原始 or 已提炼 | 原始下载/网页/PDF → 留在 Downloaded；已提炼观点才往后走 | `00-Inbox/Downloaded` |
| 2. 主领域 | 房地产 / 小孩教育 / 财商 / 其他（只能选一个） | 对应 `04-Research/` |
| 3. 房地产细分 | 按第二节子类与第三节优先级 | 对应子目录 |
| 4. 事实 or 观点 | 官方来源=事实（high）；自媒体=观点（low）+来源 | 源笔记打标 |
| 5. 去向 | 观点提炼→`01-Notes`；多篇可聚→`07-Topics`；房地产选题→`05-Content/Ideas`；纯资料→`原始资料/`（小孩教育不进入生产层） | 分流入库 |
| 6. 原始文件 | 加工完成后从 Downloaded 移入 `原始资料/` | 归档区 |

## 五、AI 判定与质量守门（方案 B：全自动＋保底闸门）

- 分类由 AI 统一判定，用户不逐条人工分类。
- AI 判定清晰（主领域、细分、去向均有直接证据）→ 自动归类，标记置信度 `high`。
- AI 判定模糊（跨领域、细分歧义、来源不明）→ 不自动入库，标记待核验，保留在 Cleaned/Downloaded。
- 质量守门不因「AI 分类」而放松：非官方来源一律标 `confidence: low` + 来源，绝不冒充事实。
- 拿不到来源的资料不入库。
- 每份知识只有一个主存放位置，不复制到多个目录。
- AI 不得输出 `verified` 分类置信度；`verified` 必须人工依据来源核验。

### 三个介入闸门

人工只做「决策」，不做「移动文件」。文件移动由 AI 自动执行。

| 闸门 | 触发条件 | 用户动作 | 文件动作（AI 执行） |
|---|---|---|---|
| ① 入库闸门 | AI 判定为低置信度/非官方来源 | 批量扫一眼待核验清单，判断能否信 | 放行→进正式库；拒绝→自动移入 `99-Archive` |
| ② 事实核验闸门 | 把某条数据当「事实」写进文案前 | 打开原始文件核对出处 | 确认后标注；不确认则不引用 |
| ③ 选题闸门 | AI 生成选题清单，进生产层前 | 从清单勾选要做的题目 | 勾选后进入 `05-Content` 创作 |

### 低置信度批量放行

- AI 每次处理 Inbox 时，把低置信度内容收拢成一份待核验清单。
- 用户集中浏览清单，对整批或逐条给出「放行 / 拒绝」决定。
- 拒绝的内容由 AI 自动移入 `99-Archive`，用户无需手动移动文件。
- 低置信度内容在用户确认前不得进入正式库。

## 六、原件归档与 Markdown 知识分层

### 原则

- **归档区保留原件**：`04-Research/房地产/原始资料/`（以及 `08-IP-品牌/` 等非知识区）保留下载时的原始格式（HTML、Word、PDF、图片），作为可溯源的证据，不作检索主体。
- **知识区必须 Markdown**：可检索、可链接、可喂给 AI 出文案的知识，一律提炼为 Markdown 笔记（`.md`，带 YAML、标签、双链）后进入 `04-Research/房地产/`、`01-Notes`、`07-Topics`。

### 禁止

- **禁止将 Word/PDF/HTML 原件直接放入知识区**（`04-Research/房地产/` 正式笔记位置、`01-Notes`、`07-Topics`）。原件一律留在归档区或品牌资产区。
- 禁止把附件当知识主体：图片、表格、原文件只在归档区，不替代 Markdown 知识笔记。

### 处理顺序

1. 下载的原始文件（任意格式）→ 先入 `00-Inbox/Downloaded`。
2. AI 读取原文 → 提炼核心 → 生成 Markdown 笔记进知识区。
3. 原始文件本体 → 移入 `原始资料/` 归档（保留原格式）。
4. 检索、双链、AI 创作一律基于 Markdown 笔记；原件仅用于溯源核验。

### 例外

- `08-IP-品牌` 是品牌经营资料库，非知识主题，允许保留原格式（.docx/.pdf/.png），供翻阅与调用。若未来需对其中内容检索/引用，再单独提炼 Markdown 索引。

### AI 工具文档

AI 工具使用/部署类文档（如 Codex 部署手册、AI-Agent 协同方案）属能力层，归 89-Prompts/AI工具使用/，不进入 04-Research/房地产。


## 七、文件转提炼转挂主题转入选题 管线（上传到选题的完整链路）

「上传了文档，选题却没增加」的根本原因：上传只是把原件放进仓库，距离选题还隔着「提炼转挂主题转入选题」三步。以下管线把这三步固化，作为 AI 处理 Inbox 后段内容的统一流程。

### 步骤与去向

| 步骤 | 判定 | 产物 | 去向 |
|---|---|---|---|
| 1. 读原件 | AI 读取原始下载（任意格式） | 判断内容本质 | 00-Inbox/Downloaded 读取 |
| 2. 判定能否提炼为知识 | 观点/方法论/可复用则能；业务/营销资料则不能 | — | 能则提炼；不能则归 08-IP-品牌 或 99-Archive，不产生选题 |
| 3. 提炼原子笔记 | 每份知识提炼一条可复用观点 | atomic-note（带 YAML、双链、confidence） | 01-Notes/ |
| 4. 挂主题 | 匹配既有 07-Topics hub；不新建主题 | 更新 hub 的 related 及原子笔记章节 | 对应 07-Topics/*.md |
| 5. 判定是否入选题 | 是否适合做视频号/公众号内容 | content-brief（status: idea） | 05-Content/Ideas/ |

### 规则点（2026-08-13 决策固化）

1. **主题归属**：能落进既有主题的一律挂既有主题，不新建 07-Topics 主题；跨领域只选一个主领域，其余放 topics，不复制文件。
2. **选题数量**：每次从候选里挑 2到3 个确定要做的进 05-Content/Ideas（status: idea），其余候选搁置、不一次性全建。
3. **A3 类方法论（IP/获客）**：属方法储备，归 08-IP-品牌，不是知识主题、不产生内容选题，仅作生产方法参考。
4. **业务/营销资料（B 组）**：不提炼为知识原子笔记、不产生选题、不进 01-Notes，维持原位置。
5. **媒体标注**：自媒体观点一律 confidence: low 并标注观点来源；其中具体数据（地价、成交额、政策数字等）未核验，引用需标注待核验。
6. **主领域**：财商为独立顶级主题域（见 ADR-018），不再并入 房地产；财商内容（财产性收入、资产配置、理财观念）主领域归 财商，涉及具体房贷/房产资产配置的内容可通过 topics 关联 房地产。
7. **低置信度内容**：在用户批量放行前不得进正式库；进入后仍按第 5 点标注，不冒充事实。
