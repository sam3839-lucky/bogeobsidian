# Knowledge Base Architecture

## 目的

本架构把“内容生命周期”和“知识主题”分开：目录表达主要职责与处理阶段，主题通过链接、属性和 Topic 页面表达。每份知识只保留一个主文件，不通过复制实现多分类。

## 内容流

```text
捕获或下载 → 清洗 → 研究或知识笔记 → 项目或内容生产 → 发布记录 → 归档
```

文件只沿流程改变主存放位置；跨领域、跨平台和跨项目的关系使用链接与后续元数据表示，不复制源文件。

## 层级与冲突规则

- 常规路径不超过三层；例外必须通过 ADR 说明。
- 发现同义目录时先列出合并影响，不自动移动或重命名。
- Topic 只做导航，不作为重复存储区。
- `96-System` 只保存治理、配置、审计和运行记录，不保存业务知识正文。
- 平台目录不得从未填写的配置推断；即使未来填写，也优先采用一份母稿加平台适配记录，而不是复制五份正文。
