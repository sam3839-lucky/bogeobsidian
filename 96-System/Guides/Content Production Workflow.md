# Content Production Workflow

## 工作流

`idea → brief → draft → review → published → repurpose 或 archived`

视频或音频内容在制作正文时可以进入 `Scripts`；`Scripts` 是形式和存放职责，不是 YAML 状态。平台未正式登记，因此当前只使用平台无关母稿和通用模板，不创建公众号、抖音、小红书、知乎、视频号等平台目录。

## 各关卡退出条件

| 状态 | 必须具备 | 下一步 |
|---|---|---|
| `idea` | 一个清楚的问题、受众假设或内容机会 | 补足角度与价值后进入 `brief`，否则归档 |
| `brief` | 目标平台（可暂为待补充）、受众、核心观点、证据需求、形式 | 证据可用后进入 `draft` |
| `draft` | 可审阅母稿或脚本，证据链接可追溯 | 进入 `review` |
| `review` | 事实、表达、版权、隐私和平台适配检查 | 通过后进入 `published`，未通过返回 `draft` |
| `published` | 真实发布日期与发布链接 | 收集表现数据，决定 `repurpose` 或 `archived` |
| `repurpose` | 明确复用对象、变化范围和新受众 | 生成新的关联 Brief，不复制成失控母稿 |
| `archived` | 记录停止原因和保留价值 | 只读保留 |

## 单一母稿原则

- 内容只保留一个主稿；不同平台版本通过关联 Brief 或发布记录表达。
- Research、Source 和 Atomic Note 只作为证据链接，不复制进内容稿。
- “房产视频文案”使用 `domain: "房地产"`，内容形式写“短视频脚本”或“口播稿”；它不是新的主领域。
- 平台未确定时写“待补充”，不猜测平台，也不建立平台目录。

## 发布与复盘

未发布时不得填写虚构日期、链接或表现数据。发布后记录可验证数据的来源与采集日期；没有采集时写“未采集”。复盘结论要区分观察、推断和下一轮实验。
