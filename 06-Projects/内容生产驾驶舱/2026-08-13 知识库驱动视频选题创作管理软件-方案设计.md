# 知识库驱动视频选题创作管理软件 方案设计

> 基于第二轮方案，探讨配套管理软件的功能设计、界面设计和操作流程。

---

## 一、现状分析：为什么需要这个软件

当前的内容生产流水线已经在 Obsidian 知识库中通过规则文档加 AI 对话跑通，但存在以下问题：

| 问题 | 具体表现 |
|------|---------|
| 状态不可见 | 无法一眼看到当前有几条内容、各自在哪个阶段 |
| 流转靠记忆 | 每个环节的退出条件依赖人脑记忆 |
| 决策分散 | 选题候选散落在多个文件里，缺乏统一 backlog 视图 |
| 核验清单手工 | 每次手动逐项打勾，容易遗漏 |
| 数据复盘断层 | 发布后表现数据记录不规范 |
| Inbox 积压 | 00-Inbox 有素材时没有主动提醒 |

核心矛盾：规则已经定义好了，但执行靠人脑记忆加手动操作。
软件要解决的核心问题：把规则变成界面，把流程变成向导，把状态变成可视化。

## 二、软件功能设计

### 2.1 功能全景图

八个功能模块：驾驶舱、选题工厂、创作流水线、数据复盘、Inbox 监控、竞品拆解库、知识库检索、设置。

### 2.2 模块一：驾驶舱 Dashboard

目的：打开软件第一眼就知道今天该做什么。

| 功能 | 说明 |
|------|------|
| 本周生产概览 | 显示本周计划、已完成、进行中、阻塞数量 |
| 待办任务卡片 | 按优先级列出待审核 Brief、待审阅爆款设计、待验收初稿、待处理 Inbox 素材 |
| 生产日历 | 月视图，标注每条内容的发布状态 |
| 阻塞预警 | 内容在某个阶段停留超过 N 天自动标红 |
| 快速入口 | 一键进入选题、创作、复盘等核心模块 |

数据来源：自动扫描 05-Content/ 下所有文件的 YAML status 字段。

### 2.3 模块二：选题工厂 Ideation

目的：管理从知识库素材到选题候选到选题清单到排期的完整流程。

| 功能 | 说明 |
|------|------|
| 选题候选看板 | 按 Topic Hub 分组展示候选选题，卡片式展示标题、切入角度、素材锚点等 |
| 选题排序 | 拖拽排序 backlog，按优先级自动推荐排序 |
| 选题筛选 | 按 Topic Hub、时效性、置信度等维度筛选 |
| 本周期圈选 | 勾选 3-5 条作为本周生产任务，一键生成选题清单 |
| 选题去重 | 自动检测与历史选题的相似度 |
| 素材关联 | 每个候选选题关联到具体原子笔记或原始资料 |
| 竞品灵感 | 侧边栏展示竞品拆解库中的可复用模式 |

### 2.4 模块三：创作流水线 Pipeline（核心）

目的：把 Brief 到爆款设计到创作到核验到发布变成可视化流水线。

流水线看板：六列 Kanban 视图，Idea / Brief / 爆款设计 / Draft / Review / Published。
拖拽卡片从一列到下一列时自动检查退出条件，不满足时阻止移动并提示缺失项。
每张卡片显示标题、创建日期、当前阶段停留天数。

关卡向导：
- Brief 阶段：表单式填写标题、目标平台、目标受众、核心观点、证据来源、内容结构、核验点
- 爆款设计阶段：3 必过项（Hook 设计 3 个方案、标题备选 3 个、情绪曲线）加 4 可选项
- 创作阶段：双栏编辑器，左侧视频号口播稿、右侧公众号文稿
- 核验阶段：发布前核验清单逐项打勾
- 发布阶段：填写发布日期、发布链接、平台

三种生产模式：
- 常规模式：从选题清单中启动，完整流程
- 热点快速响应：跳过选题候选和选题清单，直接进入 Brief，24h 倒计时
- 快速选题：从 Inbox 素材直接启动，跳过选题环节

### 2.5 模块四：数据复盘 Analytics

| 功能 | 说明 |
|------|------|
| 内容表现总览 | 表格视图：所有已发布内容的标题、日期、平台、播放量、完播率等 |
| 爆款指标对比 | 雷达图：每条内容的关键指标 vs 爆款参考线 |
| Hook 效果分析 | 按 Hook 类型分组对比不同 Hook 的平均完播率 |
| 选题效果分析 | 按 Topic Hub 分组对比不同选题方向的表现 |
| 复盘笔记 | 结构化模板：观察、推断、下一轮实验 |
| 反哺建议 | 基于复盘数据自动生成反哺建议 |

### 2.6 模块五：Inbox 监控

| 功能 | 说明 |
|------|------|
| 新素材提醒 | 检测到 00-Inbox/Downloaded 有新文件时弹出提醒 |
| 素材预览 | 预览新素材内容，支持 Markdown、图片 |
| 一键分类 | 根据分类规则自动建议分类目录 |
| 快速选题入口 | 对素材直接点击以此为选题 |
| 批量处理 | 勾选多个素材批量分类、批量归档 |

### 2.7 模块六：竞品拆解库

| 功能 | 说明 |
|------|------|
| 拆解记录列表 | 表格视图：日期、视频关键词、Hook 类型、可复用模式 |
| 拆解表单 | 结构化填写：Hook 类型下拉选择、情绪曲线拖拽描点 |
| 模式库 | 汇总所有可复用模式，按类型分类 |
| 每周提醒 | 每周自动提醒竞品拆解还未完成 |

### 2.8 模块七：知识库检索

| 功能 | 说明 |
|------|------|
| 全文搜索 | 搜索 04-Research、05-Content、07-Topics 下所有 Markdown 文件 |
| 按域筛选 | 按 domain 筛选：房地产、财商、小孩教育 |
| 按类型筛选 | 按内容类型筛选：原始资料、原子笔记、Brief、口播稿等 |
| 按状态筛选 | 按内容状态筛选：idea、brief、draft、review、published、archived |
| 素材溯源 | 从任意原子笔记或稿件一键追溯原始素材来源 |

### 2.9 模块八：设置

| 功能 | 说明 |
|------|------|
| Obsidian Vault 路径 | 配置知识库根目录路径 |
| 生产节拍设置 | 配置每周产出目标，默认 3-5 条 |
| 阻塞预警阈值 | 配置各阶段停留天数预警阈值 |
| 分类规则管理 | 查看编辑分类规则 |
| 模板管理 | 查看编辑 90-Templates 下的模板 |
| 提示词管理 | 查看编辑 89-Prompts 下的提示词 |

## 三、软件界面设计

### 3.1 整体布局

左侧导航栏加右侧主内容区域的标准布局。
导航栏包含：驾驶舱、选题、创作、复盘、Inbox、竞品、搜索、设置。
底部状态栏显示知识库连接状态和最后同步时间。

### 3.2 各模块界面设计要点

驾驶舱：
- 顶部：本周概览卡片，4 个数字卡片：计划/已完成/进行中/阻塞
- 中部：待办任务列表，卡片式，按优先级排序
- 底部：生产日历，月视图，颜色标记：绿色=已发布，蓝色=进行中，红色=延期

选题工厂：
- 左侧：Topic Hub 筛选树加竞品灵感侧边栏
- 右侧：候选选题卡片网格
- 底部：本周期选题清单，已圈选的 3-5 条可拖拽排序

创作流水线（核心界面）：
- 顶部：模式切换标签，常规模式/热点快速响应/快速选题
- 中部：Kanban 看板，6 列
- 底部：选中卡片的详情面板
- 拖拽交互：拖拽到下一列时自动检查退出条件

数据复盘：
- 顶部：时间范围选择器加内容筛选器
- 中部：关键指标卡片加图表区域
- 底部：内容表现表格，可排序可筛选

Inbox 监控：
- 顶部：新素材计数加一键处理按钮
- 中部：素材列表加预览面板
- 底部：处理历史时间线

### 3.3 设计原则

1. 极简优先：首屏不超 7 个信息模块，避免认知过载
2. 状态驱动：颜色编码严格一致，绿=完成/蓝=进行中/红=阻塞/灰=待处理
3. 一键操作：核心操作不超过 2 次点击
4. 响应式：适配桌面端 1920x1080 为主
5. 暗色模式：默认暗色主题

## 四、操作流程设计

### 4.1 日常操作流程

每日打开软件进入驾驶舱，按优先级处理待办：

1. 有待处理 Inbox 素材？进入 Inbox 监控，分类/快速选题
2. 有待审核 Brief？进入创作流水线，审核 Brief
3. 有待审阅爆款设计？进入创作流水线，审阅爆款设计
4. 有待验收初稿？进入创作流水线，验收口播稿加公众号稿
5. 有已发布待记录数据？进入创作流水线，填写表现数据
6. 无紧急待办？进入选题工厂，浏览选题候选/补充候选

### 4.2 完整生产流程

Step 1 选题：用户操作。进入选题工厂，浏览候选选题卡片，勾选 3-5 条，点击生成本周选题清单。

Step 2 Brief：AI 起草，用户审核。系统自动基于 Content Brief Template 生成 Brief 骨架，AI 填充内容，用户审核后可编辑修改。

Step 3 爆款设计：AI 生成，用户审核。Brief 通过后自动弹出爆款设计关卡，AI 自动填充 Hook 设计、标题备选、情绪曲线，用户逐项审阅。

Step 4 创作：AI 生成，用户验收。进入双栏编辑器，左侧 AI 生成视频号口播稿，右侧 AI 生成公众号文稿，用户逐句审阅。

Step 5 核验：用户逐项检查。显示发布前核验清单交互式 Checkbox，用户逐项勾选：事实核验、版权核验、广告合规、人设一致性、爆款还原度。

Step 6 发布与记录：用户操作。用户在实际平台上发布内容，回到软件点击记录发布，填写发布日期、发布链接、平台。

Step 7 数据复盘：后续。发布后 7 天系统自动提醒，AI 生成复盘笔记：观察/推断/下一轮实验。

### 4.3 热点快速响应流程

1. 驾驶舱点击热点快速响应
2. 选择热点事件类型：政策/数据/土拍/开盘
3. 输入事件简述
4. 系统自动创建 Brief，跳过 Ideation 阶段
5. 24h 倒计时：Brief 加爆款设计
6. 48h 倒计时：创作加核验

### 4.4 快速选题流程

1. Inbox 监控选中素材点击以此为选题
2. 系统自动创建 Brief，素材信息自动填充为证据来源
3. 后续流程同常规模式

## 五、技术实现建议

### 5.1 实现形态

推荐方案：Obsidian 插件

| 理由 | 说明 |
|------|------|
| 零切换成本 | 用户已在 Obsidian 中管理知识库 |
| 数据一致性 | 直接读写 Markdown 文件，不引入额外数据库 |
| 社区生态 | Obsidian 插件生态成熟 |
| 部署简单 | 一个插件文件，不需要服务器 |

备选方案：独立桌面应用 Electron/Tauri

| 优点 | 缺点 |
|------|------|
| 更灵活的 UI 设计 | 需要维护两个应用 |
| 更丰富的图表能力 | 数据同步复杂 |
| 不依赖 Obsidian 版本 | 部署成本高 |

### 5.2 数据层设计

核心原则：不做数据迁移，不引入新数据库。所有数据以 Markdown 文件加 YAML frontmatter 的形式存储在 Obsidian Vault 中，插件只做读写和展示。

### 5.3 与 AI Codex 的协作边界

本软件不替代 AI，而是作为 AI 和用户之间的桥梁：

| 软件负责 | AI Codex 负责 |
|---------|-------------|
| 状态管理、流程推进、关卡检查 | 内容生成、选题建议、竞品拆解 |
| 可视化展示：看板、图表、日历 | 爆款设计、文案创作、复盘分析 |
| 提醒通知：待办、阻塞、超时 | 事实核验、合规检查建议 |
| 数据记录与统计 | 知识库清洗、原子笔记提炼 |

1. 实现形态：Obsidian 插件 vs 独立桌面应用？推荐 Obsidian 插件。
2. AI 调用方式：软件内嵌 AI 调用还是保持当前软件管流程加 Codex 对话管内容的分离模式？
3. MVP 范围：是否同意阶段一的 MVP 范围？要不要调整优先级？
4. 开发节奏：先出方案评审多轮再开发还是边开发边迭代？
5. 与现有二创试点项目的关系：独立项目还是并入同一技术栈？
